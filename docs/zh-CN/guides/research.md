# 研究问题与实验

[文档](../README.md) · [English](../../guides/research.md)

研究问题把一个研究方向在多个 Session 和 Team 之间保持在一起：已批准的研究
简报、讨论、带证据的发现，以及每一轮工作。这里的任何操作都不会自行启动
Agent——保存简报、发表笔记或关联 Session 只是记录。

## 问题、简报与轮次

1. 在侧边栏的“研究”列表中**创建问题**。简报（标题、问题、动机、假设、约束、
   评估标准）有版本；每次编辑都会产生新版本，并与你所看到的版本进行核对。
2. 在关联的 Session 中**讨论**，把要点固定为笔记或决定。
3. 在“工作”标签页**开始一轮**。每一轮会记录它使用的简报版本，之后的修改不会
   改写它；简报更新后，该轮会被标记。
4. **记录发现**及其证据。有证据的陈述是观察；没有证据的仍然是署名的解读。
   Agent 提出的方向变更建议需要你来决定。

## 带入与带出讨论

头脑风暴常常发生在 Kubecode 之外。在“讨论”标签页：

- **导入**粘贴的文本或 Markdown，并注明来源。它会作为署名为你的原始材料保存。
  导入不会启动 Agent，不会记录发现，也不会修改简报。
- **审阅**导入内容。Kubecode 会列出它识别出的建议（问题、假设、约束、评估标准、
  决定、未决问题）。你勾选想要的条目并与当前简报对比；在你应用之前不会有任何
  改动。编辑会与你所看到的版本核对，因此不会覆盖更新的简报，新版本的备注会
  写明它来自哪次导入。针对旧简报写成的讨论会被标记，方便你对照当前已批准的
  内容审阅。
- 在“工作”标签页**开始一轮**，需要时可以引用已导入的讨论。这与以往一样是显式的
  开始一轮操作；重复提交同一请求会复用已有的轮次。
- **导出**有大小上限的讨论包（简报、进展、发现、证据名称、局限与未决问题）。
  你会预览到底有哪些内容离开工作区，自行选择要包含的部分并亲自复制。Kubecode
  不会添加对话记录、提示词、凭据、文件内容或服务器路径；你或 Agent 在发现或导入
  中写下的文字会按原样包含。每个部分都有各自的大小上限，被截断的部分会有标记。

Agent 与其他 Session 可以通过只读的上下文工具和 Composer 的“引用项目工作”选择器
找到并读取同样的材料；读取不会启动任何工作。

## 让一轮运行实验

默认情况下，一轮不能运行任何进程。要允许它，请在开始时勾选“允许这一轮运行
本地实验”（也可以稍后设置），并填写执行信封：

- **启动次数**与**同时运行的进程数**：总数与并发上限。
- **最长运行时间**：到达上限仍在运行的进程会被停止。
- **截止时间**：此后不再启动（留空表示不限）。
- **连续失败后停止**：达到后停止启动，直到你介入。
- **允许的命令**：每行一条。启动的命令必须以其中之一逐个词元开头，其他一律被
  拒绝。列出的部分之后的参数不受限制，因此只列出你愿意以任意参数运行的命令：
  允许 `sh -c` 就等于允许任意脚本。

这些限制由 Kubecode 强制执行，与 Agent 并发设置相互独立，Agent 无法提高。编辑
信封会产生新版本；已在运行的工作沿用其启动时的版本。

### 你能看到什么

每一轮的“执行”面板显示信封及其使用情况、每个已启动的进程及其状态、结果是否
仍在等待分析、退出码、输出、产物，以及 Leader 记录的决定。进程结束后一直是
“等待分析”，直到 Team 记录了决定；回合结束或消息被读取都不会改变这一点，只要
还有结果未分析，Team 就无法完成。

### 控制

- **暂停启动**只停止新的启动，已在运行的进程继续运行；**恢复启动**则相反。
- **停止**结束某个运行中的进程及其子进程。
- **取消执行**停止该轮所有运行中的进程并永久关闭信封，操作前会要求确认。
- 当 Kubecode 无法确定某个进程发生了什么（例如重启期间丢失）时会显示
  **结果未知**。它不会被当作成功，也不会被重新运行。请告知它是“从未启动”还是
  “已经结束”，这是离开该状态的唯一方式。
- 同意增加预算或范围的回复本身不会生效，必须保存新的信封版本。

### 日志与停止

每个进程的日志各保留最多 16 MiB，并以有限长度的尾部显示；进程本身不会因为输出
很多而被停止。忽略停止请求的进程会一直占用其名额，直到 Kubecode 杀掉其整个
进程组。

### 重启

Kubecode 服务器重启后，进程会继续运行。启动时 Kubecode 会读取每个进程的退出
回执，继续监视仍在运行的进程，并把无法确认的标记为未知。

## 运行实验的任务

由单个会话执行的任务可以在该轮的信封内运行自己的实验。在工作看板上：

- 实验结束后，任务进入**分析中**，直到执行会话记录这个结果意味着什么（继续分析、
  修复、重试、后续实验、等待、询问你或得出结论）。详情面板会列出这些决定。失败或
  否定的结果是证据，而不是错误。
- 详情面板中的**需要你回答的问题**列出会话提出的问题。你的回答只解决该问题，
  不会提高限制或批准更多工作。如需放宽，请修改限制或信封。
- 当限制阻止了进度或被引用的证据发生变化时，卡片会带有“需要输入”标记和
  *注意*原因。
- 任务引用的文件或结果与引用时不一致时，会显示**证据已变化**。在你查看并选择
  **接受当前版本**之前，无法接受该工作。
- 通过或驳回的评审会回贴到该工作来源的讨论串，通过的工作还会在问题日志中添加
  一条观察。

## 成员与 General Agent

每个工作区都有一个 **General Agent**（项目经理），在工作区创建时一并创建（较早创建的
工作区会在你第一次打开**设置 > 成员**时获得）。它与你澄清目标、制定计划、分派给专家、
跟进进度并向你汇报。无论指令如何设置，它都不会运行实验、编写代码、分析数据或做其他
专家工作，也不能被分配这类工作。

在**设置 > 成员**中你可以：

- 添加专家（分析、写作、代码评审或自定义）、编辑和移除；移除成员会保留其历史，若其
  仍有未完成的工作则会被拒绝；
- 查看哪些成员需要设置（例如其提供方尚未安装），修复后重试；
- 设置新工作区的默认值：General Agent 的提供方、模型等提供方选项以及它的指令。默认值
  保存在服务器上，所有浏览器一致，且不会改变现有成员。

## 把任务放上看板

**任务（Task）**就是已放上看板的研究问题。它通过对话上板，而不是表单或按钮：

1. 在 General 中讨论想法。General Agent（或某位专家）可以起草一份提案，它会出现在
   General 中，但不在看板上。
2. 通过对话完善：告诉 General Agent 需要修改什么。每个新版本都会显示在 General 中。
3. 当提案符合你的想法时，用你自己的话告诉 General Agent 把它加到看板上，不需要 @ 它。
4. 要让它开始工作，再告诉 General Agent 开始执行。这与加到看板是两个步骤，它不会设置
   任何限制或实验信封，这些仍由你决定。

只有同时满足以下条件的指令才有效：是你在 General 中亲自发的消息、不只是引用、发生在
你所认可的提案之后，并且没有被用于别的事情。专家的消息、引用你的话的 agent、重复的
文字都不会添加任务。如有不清楚的地方，General Agent 会在对话中询问。

看板只显示任务：就绪、进行中、评审、完成；等待、阻塞、暂停、需要输入是状态而不是列。
重试和内部工作都在任务之内。General Agent 汇报结果后，你可以接受（并选择结论；有充分
依据的否定结果同样可以完成任务），也可以附上理由退回。

## 在工作区里找路

导航栏最上面是四个入口：**General**（唯一的对话）、**看板**（唯一的任务看板）、**资源**（工作区产出的内容，只读
预览）和**成员**（各个 agent）。**需要你**汇总了正在等你处理的事项——待评审的结果和 agent 请求的输入——
每一项都会打开对应位置。Session、团队、话题和研究问题仍然保留，放在下方以及“历史与执行”中。

点击消息上的任务标签、看板卡片或“需要你”中的条目，会在列表旁边打开该任务；关闭后会回到你来时的那条消息。
在手机上，列表和详情是两个独立的页面。地址栏（`#` 之后的部分）始终标明你所在的位置，所以刷新、后退和分享
链接都会回到同一个位置。需要文件和 Git 时，可从标题栏的面板按钮打开；它们不会一直显示在 General 或看板旁边。

## 谁会读到你在 General 里写的内容

- 没有指名任何人的消息会交给 **General Agent**（项目经理）。你可以和它一起边想边聊、修改提案，
  并用自己的话让它把任务放上看板；不必 @ 它。
- **@提及**某位成员可以直接向其提问。只有被你点名的成员会收到消息，仅仅提及不会启动任何工作。
- 成员之间可以在 General 中交接工作。你能看到每次交接：谁写的、交给了谁。成员的消息只是汇报或请求，
  绝不是你的授权；交接链在几步之后会停下来等你。
- 与某个任务相关的消息带有**任务标签**；在“显示相关消息”里选择任务即可只看这些消息。这只是同一段对话的
  视图，不是副本。**回复**会引用一条消息，点击引用可以跳回原消息。路由提示默认折叠成一行，可展开。

## 与成员的私信

在“设置 > 成员”中选择某位成员的**私信**即可打开私密对话。只有你和该成员能看到：其他成员无法读取、搜索、
提及或引用，其中的内容也不会发到 General。**分享到 General…** 可以挑选若干轮、添加备注，并先看到将要
发布的原文；只有你确认该预览后才会发布，如果预览之后对话又有变化则不会发布。分享出去的内容就是你在
General 里的一条普通消息，所以会像其他消息一样交给项目经理。

## 在 General 与话题中写消息

General 和话题使用同一个输入框（与 agent 的私信上线后也会使用它）：

- **Enter** 发送；**Shift+Enter** 换行。在手机或平板上，Enter 换行，用箭头按钮发送；
  **Ctrl/Cmd+Enter** 始终发送。输入法（例如中文或日文）正在组字时，Enter 只用于确认候选词，
  不会发送。
- 输入 **@** 可以提及成员；用方向键和 **Enter**（或在已输入部分名称、或用方向键移动之后按
  **Tab**）选择，**Esc** 关闭列表。提及只是在消息中称呼该成员，不会授权任何工作。
- 箭头按钮用于发送，agent 工作期间也可以使用。会话里的**停止**按钮会写明它停止的 Agent。
  批准任务或接受证据始终是带文字标签的明确按钮，不会只用一个图标。
