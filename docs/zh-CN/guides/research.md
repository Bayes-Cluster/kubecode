# 研究问题与实验

[文档](../README.md) · [English](../../guides/research.md)

研究问题把一个研究方向在多个 Session 和 Team 之间保持在一起：已批准的研究
简报、讨论、带证据的发现，以及每一轮工作。这里的任何操作都不会自行启动
Agent——保存简报、发表笔记或关联 Session 只是记录。

## 问题、简报与轮次

1. 在侧边栏的“研究”列表中**创建问题**。简报（标题、问题、动机、假设、约束、
   评估标准）有版本；每次编辑都会产生新版本，并与你所看到的版本进行核对。
2. 在关联的 Session 中**讨论**，把要点固定为笔记或决定。
3. 在“工作”标签页**开始一轮**。每一轮会记录它使用的简报版本，之后的修改不会
   改写它；简报更新后，该轮会被标记。
4. **记录发现**及其证据。有证据的陈述是观察；没有证据的仍然是署名的解读。
   Agent 提出的方向变更建议需要你来决定。

## 让一轮运行实验

默认情况下，一轮不能运行任何进程。要允许它，请在开始时勾选“允许这一轮运行
本地实验”（也可以稍后设置），并填写执行信封：

- **启动次数**与**同时运行的进程数**：总数与并发上限。
- **最长运行时间**：到达上限仍在运行的进程会被停止。
- **截止时间**：此后不再启动（留空表示不限）。
- **连续失败后停止**：达到后停止启动，直到你介入。
- **允许的命令**：每行一条。启动的命令必须以其中之一逐个词元开头，其他一律被
  拒绝。列出的部分之后的参数不受限制，因此只列出你愿意以任意参数运行的命令：
  允许 `sh -c` 就等于允许任意脚本。

这些限制由 Kubecode 强制执行，与 Agent 并发设置相互独立，Agent 无法提高。编辑
信封会产生新版本；已在运行的工作沿用其启动时的版本。

### 你能看到什么

每一轮的“执行”面板显示信封及其使用情况、每个已启动的进程及其状态、结果是否
仍在等待分析、退出码、输出、产物，以及 Leader 记录的决定。进程结束后一直是
“等待分析”，直到 Team 记录了决定；回合结束或消息被读取都不会改变这一点，只要
还有结果未分析，Team 就无法完成。

### 控制

- **暂停启动**只停止新的启动，已在运行的进程继续运行；**恢复启动**则相反。
- **停止**结束某个运行中的进程及其子进程。
- **取消执行**停止该轮所有运行中的进程并永久关闭信封，操作前会要求确认。
- 当 Kubecode 无法确定某个进程发生了什么（例如重启期间丢失）时会显示
  **结果未知**。它不会被当作成功，也不会被重新运行。请告知它是“从未启动”还是
  “已经结束”，这是离开该状态的唯一方式。
- 同意增加预算或范围的回复本身不会生效，必须保存新的信封版本。

### 日志与停止

每个进程的日志各保留最多 16 MiB，并以有限长度的尾部显示；进程本身不会因为输出
很多而被停止。忽略停止请求的进程会一直占用其名额，直到 Kubecode 杀掉其整个
进程组。

### 重启

Kubecode 服务器重启后，进程会继续运行。启动时 Kubecode 会读取每个进程的退出
回执，继续监视仍在运行的进程，并把无法确认的标记为未知。
