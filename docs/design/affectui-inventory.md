# affectUI adoption inventory

Maintained disposition of the public affectUI catalog against Kubecode, and the
per-file integration ledger for the programme in
[Bayes-Cluster/kubecode#276](https://github.com/Bayes-Cluster/kubecode/issues/276).

- Planning and evidence baseline: `main` at `378b03569502b1b3317b3c3623271ae3b2f80135`; catalog captured 2026-10-26.
- Decisions (`Recreate` / `Adapt` / `Defer` / `No fit`) are owned by the slice
  issue in the row and are not re-litigated here; this document tracks their
  implementation state and the file-level ownership.
- `Deferred` is a data/capability gap, not a hidden acceptance dependency.
  `Closed (no fit)` deliberately excludes the entry from this product.
- Every implemented row records its reference URL, style variant (the public
  **Clean** preview is the initial visual baseline), capture date, the exact
  parts reproduced, deviations, and the fixture/evidence that proves it, in the
  owning component's documentation block and the owning slice's evidence.
- App Shell Workspace Flat is the primary overall frame (slice C, #279).
- Regenerated from the slice issues' mapping tables at the baseline SHA; update
  the implementation-state column as slices land, one PR at a time.
